Grain & Hierarchy Assessment

Decision: Position grain, not Trade grain. Individual trades belong in the source TMS/OMS (Bloomberg AIM, Murex, Aladdin). This DW receives aggregated positions from batch jobs — one row per Book × Instrument × Snapshot. Replicating trade-level data here would add millions of rows per day with no incremental analytical value for a management dashboard; trade-level queries should hit the front-office system directly.

DIM.Desk denormalises BusinessLine and Division rather than creating separate snowflake tables. With only 2–3 business lines in scope (CPT / Treasury / ALM), a separate DIM.BusinessLine table adds join cost without enabling new analyses not already available via desk-level grouping. This aligns with the Kimball Bus Architecture recommendation for short, stable hierarchies.

Dimension Table DDL — Full Specification

All dimension tables are in schema DIM of the TreasuryDW database. Integer surrogate keys (IDENTITY) are generated in the DW; business/natural keys are retained for drill-through. SCD Type 1 (overwrite) unless otherwise noted. DIM.Portfolio is a snowflake extension of DIM.Desk — it does not duplicate desk attributes; those are resolved by join at query time.

Conformed Dimensions

-- 15-minute grain (96 rows/day)
-- Matches intraday snapshot cadence

-- Powers scenario toggle in SSAS
-- Calculation Group & dashboard UI

-- BSLimitUSD is Treasury-set; updated

  -- 2-3 business lines in scope; separate

  -- without enabling new analyses.
  BusinessLineCode  VARCHAR(20),
  -- 'CIB' | 'MARKETS' | 'TREASURY_ALM'
  BusinessLineLabel VARCHAR(40),
  -- 'Corporate & Institutional Banking'
  -- 'Treasury & ALM'

  -- 'STRUCTURED'       (CLO/ABS)
  DivisionLabel     VARCHAR(60),
  Hat               VARCHAR(10),
  -- 'CPT' | 'TSY' | 'BOTH'
  -- maps DivisionCode to dual-hat lens
  RatingFocus       VARCHAR(10),
  -- 'IG' | 'HY' | 'EM' | 'MIXED'
  InstrumentFocus   VARCHAR(20),
  -- 'CASH_BOND'|'CDS'|'CLO'|'INDEX'
  RegionFocus       VARCHAR(10),
  -- 'US' | 'EU' | 'EM' | 'GLOBAL'
  DeskHeadName      VARCHAR(60),
  BSLimitUSD        DECIMAL(18,2),
  LCRDragLimit_PP   DECIMAL(7,4),
  -- max pp contribution to LCR drag
  FTPGroupCode      VARCHAR(20),
  -- FTP pool membership
  IsActive          BIT           DEFAULT 1,
  EffectiveFrom     DATE,
  EffectiveTo       DATE          NULL
);
-- DIM.Strategy
-- Sub-classification within a desk
-- CPT may run multiple strategies

  StrategyCode   VARCHAR(30)  NOT NULL UNIQUE,
  StrategyLabel  VARCHAR(80),

  -- strategy belongs to a desk
  RatingFocus    CHAR(5),
  InstrumentType VARCHAR(30),
  HoldingPeriod  VARCHAR(15),
  -- 'INTRADAY'|'SWING'|'CORE'
  IsHedgeStrategy BIT,
  FTPPoolEligible BIT,
  BSConsumption  VARCHAR(10),
  -- 'HIGH'|'MEDIUM'|'LOW'|'ZERO'
  -- CDS = ZERO (unfunded)
  Description    NVARCHAR(200),
  IsActive       BIT          DEFAULT 1
);
DIM.Portfolio (Book) · "Portfolio" and "Book" are used interchangeably across TMS platforms (Bloomberg AIM: Book; Murex: Portfolio; Aladdin: Portfolio). Each trade in the TMS is tagged to a Book at execution. This DW does not store individual trades — it receives net positions (Book × Instrument aggregates) from batch jobs. DIM.Portfolio is therefore the bridge between the trade-level source world and the position-level DW grain. Facts retain DeskKey as a denormalised FK so desk-rollup queries avoid the Portfolio→Desk join. 
-- DIM.Portfolio
-- Snowflake extension of DIM.Desk.
-- GRAIN: one row per named portfolio/book.
-- Trades in FCT.PositionSnapshot are booked
-- at portfolio level. DeskKey is retained in
-- facts as a denormalized FK for performance
-- (avoids Portfolio→Desk join in every query).
-- SCD Type 2 on DeskKey if portfolios can
-- be reassigned between desks over time.
CREATE TABLE DIM.Portfolio (
  PortfolioKey     INT  IDENTITY(1,1) PRIMARY KEY,
  PortfolioCode    VARCHAR(30)  NOT NULL UNIQUE,
  -- e.g. 'IG_CASH_A', 'HY_CASH_MAIN'
  --      'CDX_MACRO_HEDGE', 'EM_LATAM'
  PortfolioName    VARCHAR(80),
  DeskKey          INT  NOT NULL
                   REFERENCES DIM.Desk(DeskKey),
  -- N portfolios : 1 desk (snowflake)
  PortfolioType    VARCHAR(20),
  -- 'TRADING'       : normal risk book
  -- 'BANKING_BOOK'  : accrual / AFS
  -- 'HEDGE'         : macro/micro hedge
  -- 'REPO'          : financing book
  -- 'INDEX'         : CDX/iTraxx tracking
  BaseCurrency     CHAR(3)     DEFAULT 'USD',
  BookingEntity    VARCHAR(20)  NULL,
  -- legal entity code for default booking
  IsHedgeBook      BIT         DEFAULT 0,
  -- flag for hedge accounting designation
  IsHedgeTarget    BIT         DEFAULT 0,
  -- the portfolio being hedged (not the hedge)
  HedgeTargetPortfolioCode VARCHAR(30) NULL,
  -- FK to self: which book does this hedge?
  BSLimitUSD       DECIMAL(18,2) NULL,
  -- portfolio-level BS limit (NULL = use desk)
  RiskLimitCS01    DECIMAL(18,2) NULL,
  -- max CS01 notional (USD/bp)
  RiskLimitDV01    DECIMAL(18,2) NULL,
  -- max DV01 notional (USD/bp)
  FTPGroupCode     VARCHAR(20)   NULL,
  -- FTP pool assignment (may differ from desk)
  ReportingGroup   VARCHAR(30)   NULL,
  -- roll-up label for P&L reporting
  IsActive         BIT           DEFAULT 1,
  EffectiveFrom    DATE          NOT NULL,
  EffectiveTo      DATE          NULL
  -- NULL = currently active
);

-- FCT.ActionItem

-- 4-row lookup: AMER | EMEA | APAC | GLOBAL
-- Referenced by DIM.Country (RegionKey FK).

CREATE TABLE DIM.Region (
  RegionKey      INT  IDENTITY(1,1) PRIMARY KEY,
  RegionCode     CHAR(5)     NOT NULL UNIQUE,

-- DIM.Country
-- ISO 3166-1 country reference.
-- RegionKey links to DIM.Region (snowflake).
-- Replaces free-text Country CHAR(3) columns
-- in DIM.Instrument, DIM.Issuer, DIM.LegalEntity.
-- IsSanctioned / IsEU drive regulatory alerts.
-- EM classification drives LCR HQLA Level 2B
-- eligibility for sovereign bonds.
CREATE TABLE DIM.Country (
  CountryKey     INT  IDENTITY(1,1) PRIMARY KEY,
  ISO2           CHAR(2)      NOT NULL UNIQUE,
  -- ISO 3166-1 alpha-2: 'US','GB','SG','JP'
  ISO3           CHAR(3),
  -- ISO 3166-1 alpha-3: 'USA','GBR','SGP'
  CountryName    VARCHAR(60),
  RegionKey      INT  NOT NULL
                 REFERENCES DIM.Region(RegionKey),
  -- snowflake: Country belongs to a Region
  SubRegion      VARCHAR(20),
  -- 'W_EUROPE'|'N_AMERICA'|'SE_ASIA'
  -- 'LATAM'|'MENA'|'SSA'
  PrimaryCurrency CHAR(3),
  -- ISO 4217: 'USD','GBP','SGD','JPY'
  CentralBank    VARCHAR(15),
  -- 'FED'|'BOE'|'MAS'|'BOJ'
  IsG10          BIT,
  -- G10 currency countries
  IsG20          BIT,
  IsEU           BIT,
  IsEEA          BIT,
  IsEM           BIT,
  -- MSCI EM classification
  IsFrontier     BIT,
  IsSanctioned   BIT,
  -- OFAC/HM Treasury/EU sanctions
  IsFATFGrey     BIT,
  -- FATF grey list
  SovRatingBucket CHAR(5),
  -- 'AAA'|'AA'|'A'|'BBB'|'HY'
  HQLASovEligible BIT,
  -- sovereign bonds eligible for LCR Level 2B
  IsActive       BIT          DEFAULT 1
);

-- DIM.RiskFactor
-- One row per market observable used

CREATE TABLE DIM.RiskFactor (
  FactorKey        INT  IDENTITY(1,1) PRIMARY KEY,
  FactorCode       VARCHAR(50)  NOT NULL UNIQUE,
  -- e.g. 'CDX_HY_5Y', 'UST_10Y'
  --      'SOFR_ON', 'USDJPY_XCCY_3M'
  FactorLabel      VARCHAR(80),
  AssetClass       VARCHAR(20),
  -- 'RATE'|'CREDIT'|'FX'|'REPO'
  -- 'EQUITY_VOL'
  SubClass         VARCHAR(20),
  -- 'GOVT'|'XCCY_BASIS'|'IG_SPREAD'
  -- 'HY_SPREAD'|'EM_SPREAD'
  Tenor            VARCHAR(10)  NULL,
  -- '1M','3M','6M','1Y','2Y','10Y'
  Tenor_Days       SMALLINT    NULL,
  Unit             VARCHAR(10),
  -- 'BPS'|'PCT'|'SPOT'|'VOL'
  BloombergTicker  VARCHAR(50),
  ReutersTicker    VARCHAR(50),
  ICETicker        VARCHAR(50),

Implementation Architecture — Data Pipeline Stack

Data flows left-to-right through five technology layers. SQL Agent (bottom bar) orchestrates job scheduling and failure alerting across all layers. The SSAS Tabular model runs in hybrid mode: Import for EOD/historical facts, DirectQuery for intraday snapshots (IsCurrentSnapshot = 1).

Read direction: Source Systems feed SSIS packages every 15 min (intraday) and at three batch windows (SoD 06:00-08:00, EoD 19:00-21:00 ET). SSIS lands data into SQL Server staging, then upserts into DIM/FCT tables. SSAS processes the Tabular model post-load. Power BI connects live to SSAS -- no data import into the BI layer.
